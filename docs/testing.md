# Testing

People depend on these packages, so every platform is tested against the **same scenario catalogue**.

## The scenario catalogue

`examples/shared` (`@stacklatte/chart-examples`) defines 35 reproducible scenarios with seeded data — identical on every run and every platform:

| Kind | Scenarios |
|---|---|
| **Feature** (20) | Basic, Line, Indicators, Bollinger, RSI, MACD, Volume, OHLC HUD, Trade Markers, Custom Panel, All Panels, Custom Theme, Light Theme, **ChartConfig pipeline** (incl. VWAP), 12-hour time, no grid, max zoom, RSI(7), line + markers, auto-range custom panel |
| **Stress** (2) | 2,000 candles with overlays + RSI + HUD; **50,000 candles** with every panel and overlay |
| **Live** (2) | a new candle every 2 s; a tick every 100 ms (capped at 10,000 candles) |
| **Edge** (11) | no data, 1 candle, 5 candles, flat market (zero price range), prices ≈ 1e9, prices ≈ 1e-6, unsorted + duplicate candles, gaps, a **dirty feed** (NaN / Infinity / null candles, garbage volume), an invalid indicator period, **scrambled markers** (unordered, one off-screen) |

Every demo serves the same URL shape (`/#/scenarios/<id>`) and the same test ids (`tab-<id>`, `title`, `chart-host`, `stats`), so one suite drives them all. To add a scenario, add it to `examples/shared/src/scenarios.ts` — every suite below picks it up, and the native Maestro flow is regenerated by `npx tsx e2e-native/generate-flows.mjs`.

## The matrix

| Layer | Command | What it proves |
|---|---|---|
| Engine unit + fuzz | `npm test -w @stacklatte/chart-engine` | indicator math, viewport math, dirty-data robustness, up to 1,000,000 candles |
| Schema ↔ validator parity | (part of the engine tests) | the JSON Schema given to LLMs and the runtime validator agree (fuzzed) |
| Renderer unit | `npm test` | every scenario mounts, survives hostile gestures, resizes, panel toggles and 100 live ticks in `ChartController` (the Angular renderer), React and Angular |
| Browser e2e | `npm run test:e2e` | every scenario in Chromium on **React and Angular**; real drag / wheel / hover; stress and live **performance budgets** |
| Native e2e | `npm run test:native` | all scenarios on an **iOS simulator** via Maestro (generated from the catalogue), incl. the 50k stress scenario |
| **Renderer oracle** | `npm run test:e2e` (project `oracle`) | every scenario is rendered by the **published `chart-react` 1.3.2** and by this workspace, then every canvas pixel and the HUD text are compared — only three documented fixes may differ |
| **Native compat** | `npm run test:native:compat` | the same React Native app on a simulator with **`chart-native`**, the new **`chart-core` shim** and the **published `chart-core` 2.3.3**, pixel-compared |
| Feature coverage | (part of `npm test`) | every `ChartProps` field must be set by a scenario or explicitly listed as covered elsewhere — adding a prop without a decision is a compile error |
| Consumer smoke | `npm run test:pack` | packs every package and installs the tarballs into a clean project (ESM + Angular) |
| Contracts | `npm run test:contracts` | public API locked per package; **backward compatibility against the published `chart-core` 2.3.3 / `chart-react` 1.3.2** (same numbers, same exports); docs checked; size budgets |

## Backward compatibility

The contract tests download the packages that are actually published and prove the new code is a drop-in replacement: every export still exists, constants are identical, and the old and new engines produce **identical output** for indicators, geometry, layout, ticks and `ChartConfig` compilation on every scenario. Behaviour that changed on purpose (invalid enums now rejected, undrawable candles dropped, invalid periods return no data) is listed in the test and asserted explicitly.

## Docs are tested too

`compat/src/docs.test.ts` fails the build if any documentation imports a symbol that does not exist, contains a `ChartConfig` that does not validate, binds an `<sl-chart>` input that does not exist, links to a missing file, or contains a complete TypeScript example that does not compile. Mark an intentionally invalid config block as `json invalid`, and a non-compilable illustration as `ts nocheck`.

## Running everything

```sh
npm install
npm run build
npm test                 # unit tests across all packages
npm run test:e2e         # browser e2e + performance budgets (Chromium)
npm run test:pack        # tarball smoke test
npm run test:contracts   # API locks, compatibility, docs, sizes
npm run test:native      # iOS simulator + Maestro (see e2e-native/README.md)
```
